# Revit 數量計算 Excel 經驗教訓

## L-001：房間相鄰不等於開口位於房間計算邊界

門窗的 `FromRoom`、`ToRoom` 只能證明開口與房間有關，不能證明其宿主牆屬於房間的粉刷或踢腳邊界。扣除開口前，必須先取得 `GetBoundarySegments(Finish)` 的宿主元素集合，再確認門窗宿主牆 `ElementId` 位於該集合。F212 的「廁所門-60x200 cm」就是必要回歸案例：如果廁所隔牆不是 F212 的計算邊界，就不得扣除。

## L-002：房間型算量應以完成面邊界的全部迴圈為準

踢腳、內牆粉刷與空間表周長應優先使用 `SpatialElementBoundaryLocation.Finish`，並累加 `GetBoundarySegments` 回傳的全部邊界迴圈。只取第一圈會漏掉內圈、柱洞或房間包覆的其他空間；直接使用 Revit `ROOM_PERIMETER` 則可能是牆中心線結果，與實際裝修面不一致。

## L-003：完整房間明細與有數量項目是兩個不同集合

Excel 的房間列應包含全部有效房間，即使房間沒有踢腳、粉刷或特定材料，其對應數量仍可為 0 或空白。BS101 至 BS110 是完整性回歸案例。只有材料類型欄可以依專案是否實際存在而省略，不能因此刪掉房間列。

## L-004：有實體天花板時不得退回上層樓板底

內牆粉刷淨高的證據順序應為：房間上方實體天花板、天花板高度參數或幾何底面、上層樓板底。偵測天花板時要用房間平面範圍內多點採樣或水平投影相交，不能只用房間中心點。F110 的 `C2-明架礦纖天花板 (綠建材、耐燃一級)` 高度偏移 3.2 m 是必要回歸案例；輸出 5.05 m 代表錯誤退回樓板底。

## L-005：淨高計算保留完整精度，顯示值最後才取整

所有 Revit 內部英尺轉公尺、標高差、樓板厚度與偏移量應先以完整精度運算。業務要求整數淨高時，只能在最終顯示或套用公式前依規則取整，不能逐段四捨五入。Excel 應保留 `高度來源` 或診斷資料，讓使用者能分辨天花板、樓板底與幾何射線結果。

## L-006：輕隔間牆高與房間淨高不能共用單一算法

一般輕隔間優先使用「上層樓層標高 - 上層樓板厚度 - 牆基準樓層標高 - 牆基準偏移」；遇到 Revit `貼附頂/底`、斜板或局部降板時，再採牆頂附著資訊與幾何射線。低矮牆、襯板類牆則保留自身 Revit 牆高，避免 Type-B 濕式輕隔間襯板因被套用整層樓高而面積暴增。

## L-007：開口名稱與扣除依據必須分開處理

Excel 名稱欄應採 Revit 門窗品類的類型名稱，例如 `D5a-120x220 cm`；扣除資格則由宿主牆與邊界關係決定。不能因類型名稱含「廁所門」就一律扣除或排除，也不能以名稱取代幾何和宿主驗證。

## L-008：Excel 是可稽核成果，不只是數值快照

報表標題應取目前 Revit 文件名，不得殘留範本專案名稱。數量儲存格應保留周長、淨高、開口扣除等公式，最下方建立 `SUM` 總計並標示「數量總計」。正式覆寫前保留備份，並以舊版與新版總量差異追查規則變更。

## L-009：pyRevit 與 RevitMCP 共用規則，但執行層需分離

pyRevit 一鍵匯出可作為目前可執行的參考實作；RevitMCP 應把邊界擷取、開口判斷、淨高推導、材料映射與 Excel 寫入拆成可測試的服務或工具。Skill 負責選擇流程與驗證，不能把 GUI 腳本的狀態或硬編碼專案名稱當成 MCP 契約。

## L-010：天花材料欄以房間 C 代碼為主，面積優先採實體天花

天花 Excel 不需要再讓使用者複選粉刷明細表。Room 的 `天花板塗層` 已能直接決定 C1、C2 等材料欄，明細表篩選反而可能漏掉有效房間。實體天花的類型標記／Type Mark 只作一致性檢核：若與 Room C 代碼不同，材料欄仍依 Room 參數填入，但必須提示「實體天花需更改」並列出兩邊代碼。Room 代碼空白時也不得拿實體 Type Mark 代填，應保持無材料數量並提示回填 Room 參數。面積欄則要優先採房間上方命中的 `OST_Ceilings` 實體面積，沒有有效實體天花時才回退 Room 面積；F506 至 F511 這類上方有 C2 實體天花的挑空房間，不可因淨高檢核排除上層天花就改用整房 Room 面積。

目前天花 Excel 範本主表為 3 個固定欄：A 編號、B 空間名稱、C 面積；材料欄從 D 欄開始，資料列從第 8 列開始，總計列公式從 `D8` 起加總。不要再輸出舊版 D 欄「面積修正」，否則會讓材料欄整體右移並破壞使用者現在沿用的格式。

## L-011：跨房間與跨樓層的實體天花必須同時切分

天花與 Room 的 bbox／取樣命中只能證明兩者有覆蓋關係，不能證明整個 `HOST_AREA_COMPUTED` 都屬於該房間。F131 的 Room 面積約 35.041 m²，但舊結果為 1220.906 m²。回讀模型後確認，除了同層 Ceiling 跨越多房間，舊邏輯還只比較樓層棟別字首 `B`，使 B-1F Room 可能把 B-2F、B-3F 等同 XY 位置天花一起加總。

正確作法分兩道：先保留 Room 同基準樓層的天花；同層沒有候選時，才取最近上方候選樓層，支援挑空房間。再以 Room `GetBoundarySegments(Finish)` 建立垂直裁切實體，與 Ceiling Solid 做布林交集，取交集實體的向上表面面積作為房間天花覆蓋量。幾何裁切失敗才可使用 bbox／房間內取樣估算，且估算值不得超過 Room 面積；稽核表必須標示面積來源與垂直排除訊息。

## L-012：混合天花可能同時存在模型與 2D 圖面，材料面積不可整房複製

F140 的 Room `天花板塗層=C4+C9`，C4 是實體 `OST_Ceilings`，C9 可能只畫成天花平面視圖中的 FilledRegion。只比對實體天花會把 C9 誤報為缺少；若又讓 C4、C9 兩個材料欄都使用 `=C列`，整間面積會被重複計量。

舊流程曾嘗試掃描圖紙或已配置視圖名稱含「天花」的 CeilingPlan，並從 FilledRegion 類型參數或標籤取得 C 代碼；但實務上 FilledRegion 常跨房間一次繪製，幾何交集不一定代表材料分區，而且掃描所有圖紙會明顯拖慢匯出。

新版流程不以 FilledRegion 幾何面積作天花數量。當 Room 代碼恰好等於已知實體代碼加上一個唯一剩餘代碼時，剩餘代碼優先用 `Room 面積 - 實體天花面積` 反推；例如 F140 應以 C4 實體面積從 Room 總面積扣回 C9，而不是直接相信表現用 FilledRegion 是否精確貼齊。主表「備註」只寫需要修正或判讀的異常，正常反推公式與概算容許差異不必佔據主表備註，完整證據保留在稽核分頁。

## L-013：數量表主備註要降噪，正常概算差異不要寫成錯誤

天花 Excel 的主表備註應服務人工審閱，而不是列出所有 debug 細節。正常反推、垂直排除、實體天花面積與 Room 面積的概算落差，不在主表備註特別敘述；完整來源留在稽核分頁。主表備註優先保留真正需要處理的事項：Room `天花板塗層` 缺漏、Room C 代碼與實體 C 證據不一致、剩餘代碼不只一個而無法反推、或面積差異明顯到可能影響數量。

## L-014：地坪多代碼可能是施工層，不是面積分區

地坪 Room `樓板塗層` 同時出現多個 F 代碼時，常代表打底面、完成面、防水層等不同工序，各工序都以整間 Room 面積計量。不可套用混合天花的分區邏輯而只填一欄或要求分攤；每個已由材料版確認且不含「基座」的 F 欄都應保留 `=C列` 公式。材料名稱含「基座」時，基座不是整間地坪面積，該材料欄不得自動帶值，備註應明確提醒「此房間有基座需自行手動計算填入數值」。若材料版無法解析某個 F 代碼的名稱，也先留白，不可在尚未排除基座可能性前灌入整間面積。房間排序另依專案 Level 命名脈絡套用 `floor-level-ordering`，避免把棟別字首誤當地下層。
