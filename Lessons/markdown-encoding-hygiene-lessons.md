# Markdown 編碼衛生 Lessons

## L-001: 知識文件和 legacy Excel 不是同一種編碼問題

`.md` 知識文件應維持 UTF-8，`.xls` 與 Excel COM 相容性則是另一條問題線。不要把處理舊 Excel 的編碼慣性帶到知識文件。

## L-002: `Default` 能讀不代表檔案就該存成系統碼頁

Windows 上某些工具會用系統預設碼頁讀檔。這只能說明工具行為，不代表文件本體應該配合降級。知識文件仍應優先維持 UTF-8。

## L-003: 大量 `?` 幾乎都是寫壞，不是讀壞

如果 hex 裡的中文區段已經變成大量 `3F`，通常代表內容在先前寫回時就被替換掉了。這種情況再做編碼轉換只會放大損傷，應直接重建內容。

## L-004: 先驗證讀取端，再動檔案本體

看到亂碼時，第一步應是改用 `UTF8` 顯式讀取、檢查 hex、或比對不同讀法。先確認是哪一端出錯，再決定要不要重寫文件。

## L-005: SKILL 驗證失敗不等於整份知識系統都該改碼

若某個 skill 驗證腳本以系統預設編碼讀 `SKILL.md`，應優先修腳本或讓 `SKILL.md` 暫時保持 ASCII 安全，而不是把 Domain、Lessons 一起改成 cp950。
