# pyRevit_Tools — Revit 內建按鈕擴充（pyRevit extension）

本資料夾與專案主系統的關係是「**並列、互補、非取代**」。獨立於 `scripts/` 與 `MCP/` 而存在，原因如下。

## 單一 Tab：`MCP_Macros.tab`

| Tab | 實作路線 | 依賴 |
|-----|---------|------|
| `MCP_Macros.tab`（MCP 巨集 🦞） | **以 DLL 橋接為主**：透過 `lib/mcp_bridge.py` 直呼已載入的 `RevitMCP.dll` 的 `CommandExecutor`；少數按鈕可直接用 Revit API/檔案 API | pyRevit；橋接型按鈕另需 RevitMCP add-in 已安裝 |

> 原本另有 `MCP_Schedules.tab`（純 Python 直呼 `Autodesk.Revit.DB` 建立標準 MEP 採購明細表），
> 2026-07-28 依使用者需求移除（用不到）。

### DLL 橋接原理（`lib/mcp_bridge.py`）

pyRevit 腳本跑在 Revit 行程內的 UI 執行緒（API context），可以直接建構
`RevitMCP.Core.CommandExecutor` 並呼叫 `ExecuteCommand`——與 AI 對話走的是
**同一套 C# 演算法**：

- **零重寫**：降樑貼齊、IFC 同步等大型演算法不用翻成 Python
- **不經 WebSocket**：不佔用 8964 連線，MCP 服務未啟動也能用
- **同步演進**：C# command 修好 bug，按鈕自動受益

```python
import mcp_bridge as mcp
data = mcp.run('renumber_rooms_by_level',
               {'level': '2FL', 'startNumber': '201', 'dryRun': True})
```

## 跨層群組投影（DirectContext3D）

入口：**MCP 巨集 → 視覺化 → 跨層群組／投影比對**。在排水平面視圖啟動，展開下拉清單，搜尋並勾選其他平面視圖的詳圖群組，再按「更新投影」。視窗保持開啟，可同時平移、縮放 Revit 圖面。

- 依來源與目標樓層的實際高程區分：上方暖色、下方冷色、同高／未知灰色。多選群組使用不同色票；圖例、滑鼠提示與結果文字均列出群組、來源視圖、樓層、ID、色碼。
- 保留專案 XY，將群組線形投影至目前視圖剖切平面。巢狀群組遞迴讀取；不再次套用群組／實例變換。完全相同的線段以交錯色段表示多個來源，沒有移動管位。
- 支援細部線、詳圖元件可讀曲線及巢狀實例；讀取 UP/DN 狀態供查閱。TextNote 使用近似文字輪廓，填充區域顯示邊界。族群內標籤、遮罩、填充紋樣及無法讀取的元素會在結果中提示；不是原生詳圖的完整複製。
- 投影只屬於指定文件／視圖。切換樓層後按「讀取目前視圖」重新選擇；模型變更會停用舊投影，按「更新投影」重讀。可取消讀取；清除投影或關閉視窗會移除自己的繪圖服務。
- 投影頂點放在目前視圖 Top Clip 前緣以減少模型深度遮蔽；DC3D 包圍範圍加上小厚度避免共面線被剔除。視窗即時顯示 RenderScene／CanExecute／包圍範圍回呼計數，供診斷空白畫布。
- 這是暫時視覺比對，沒有建立或修改 Revit 元素，也沒有自動判定接續、撞梁柱或落水頭是否落在天溝。投影線不是可選取的 Revit 元素，其來源提示位於視窗圖例。Revit 圖像匯出可能包含當下投影，正式輸出前請清除。

使用 pyRevit IronPython 2.7，不依賴 MCP 連線或更新 RevitMCP DLL。首版以本機 Revit 2020 API 簽章及離線測試驗證；**實際圖面顯示仍需實機驗收**。DirectContext3D 的服務與顯示方式參考 [Autodesk 說明](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Basic_Interaction_with_Revit_Elements/Views/Revit_API_Revit_API_Developers_Guide_Basic_Interaction_with_Revit_Elements_Views_Displaying_Graphics_with_DirectContext3D_html.html)。

新增按鈕後須重建 pyRevit 快取：先存檔並完全關閉 Revit，再於專案根目錄執行 `scripts/pyrevit-refresh.ps1`，重新啟動 Revit。驗收順序：單選上層、單選下層、上下多選、同位置重合、切換視圖、修改來源後更新、清除與關閉視窗；確認圖例色碼、UP/DN 圖形與原圖一致。

> 門開口依 `FromRoom` / `ToRoom` 扣到兩側房間，踢腳為 `-` 或空白的放置房間仍列入明細，
> 材料名稱優先讀取使用者選定的材料版族群類型名稱，

> 淨高優先偵測房間內 `OST_Ceilings` 實體天花板底，若無實體天花板則用「房間基準樓層到上層樓板底」，

## 為什麼獨立在 root（不是 `scripts/`、不是 `MCP/`）

| 候選位置 | 為什麼不適合 |
|---------|------------|
| `scripts/` | 是 Add-in **安裝/部署 PowerShell/Bash 腳本**（build、deploy、port release）。pyRevit pushbutton 是「Revit 內 user-facing 按鈕」，執行環境與用戶完全不同 |
| `MCP/` | 是 **C# .NET Revit Add-in 源碼**（單一 `RevitMCP.csproj` 多版本 build）。pyRevit 用 Python+IronPython，技術棧不一致 |
| **root**（現狀）| pyRevit 載入 extension 用「user folder symlink → 此目錄」的標準慣例。`.extension/.tab/.panel/.pushbutton` 是 pyRevit 強制目錄結構，搬位置會破壞 pyRevit 發現邏輯 |

## 與 MCP 主系統的關係

- **非 MCP tools**：本目錄的功能 *不是* 透過 `MCP-Server/src/tools/` 開放給 AI Client 的 tool。Claude / Gemini 看不到、也叫不到它
- **MCP 巨集 = 同後端的人工入口**：AI 走「stdio → MCP Server → WebSocket → CommandExecutor」，按鈕走「pyRevit → DLL 橋接 → CommandExecutor」，殊途同歸
- **備援**：當 MCP Server 沒開（離線、不想開 AI），設計師仍可用按鈕跑同一套演算法
- **被 domain 文件引用**：`domain/dependent-view-crop-workflow.md` 提到「AI 可參考此程式碼邏輯，引導使用者自行建立 Python 腳本」

## 部署方式

pyRevit 標準作法（使用者一次性設定）：

1. 安裝 pyRevit（<https://github.com/eirannejad/pyRevit>）
2. pyRevit CLI：`pyrevit extend ui MCP_Tools <絕對路徑>/pyRevit_Tools/MCP_Tools.extension`
   - 已安裝過的話：pyRevit 設定 → Reload，或 `pyrevit extensions update MCP_Tools`

## 測試 Checklist（首次部署後逐顆點檢）

- [ ] 門窗編號重複 — 選編號來源與判定方式；同型號多樘共用編號在「門窗表讀法」下不得報錯；`Ｄ１`／`d 1`／`D1` 必須收斂成同一組；排除帷幕時該筆只分流不消失
- [ ] 門窗編號補空值 — 只填空白、既有編號不得被覆蓋；寫類型註記時同型號只寫一筆並標示影響樘數；填入值撞到既有編號要被擋；流水號模式有阻擋時整批不給套用
- [ ] 重疊車位檢核 — 整排相鄰車位不得誤報；複製重疊的兩個車位要抓到並回報重疊深度；不同樓層的車位不得互相比對；斜放車位不得因外框相交而誤報
- [ ] 視圖比例管理 — 檢視模式列出的比例與 Revit 屬性一致；同一視圖貼在多張圖紙上只出現一筆；受視圖樣板控制的視圖要被擋下並顯示樣板名稱；套用後提示重跑視埠類型同步
- [ ] 自動放置面積 — 健檢模式手動製造未放置／未封閉／多餘各一，三種狀態要分類正確；放置模式先在單一樓層跑，預覽數＝實建數；**同參數立刻再跑一次必須是 0 筆**（冪等）；故意讓一條面積邊界線開口→該筆標記未封閉且整批拒絕套用；中途取消→模型 Area 數量不變
- [ ] 面積重新編號 — 位置排序在同一排的面積要照左→右；**刻意做出 A1↔A2 互換的情境，套用後兩者必須真的對調且沒有留下重複編號**；範圍選單一平面時，其他樓層已佔用的編號要被擋；預覽的新舊對照與實際結果一致
- [ ] 複製面積到其他計畫 — 邊界線與面積都要出現在目標計畫且位置正確；**同參數立刻再跑一次必須是 0 條 0 個**（邊界線與面積都不得加倍）；目標已有同編號的面積要被擋；只複製面積而目標沒有邊界時該筆要標未封閉並整批拒絕
- [ ] 區域線重新生成 — Center 模式下相鄰房間的共用牆只能產生一條線；**同參數立刻再跑一次必須是新增 0 條**；弧形牆產生的必須是弧不是一堆短直線；選「先刪除既有」時預覽的刪除數要與實際一致；清理重複模式跑完再跑一次應為 0 條。**依牆模式另驗**：拿一道 Location Line 設為「牆面」的牆，牆心模式產生的線必須真的在牆中央而不是貼著牆面；核心模式在不對稱層構造（如 20/250/30）下，兩條線到各自牆面的距離必須分別是 20 與 30；帷幕牆與堆疊牆要被略過並說明原因
- [ ] 區域線重新生成（依連結模型的牆，JAC 04.10）— **連結模型有位移或旋轉時，產生的區域線必須落在連結牆的實際位置上**（`GetTotalTransform` 有生效）；**牆心以外的模式（核心層／牆面）偏移方向要正確**——法向量走 `OfVector` 而非 `OfPoint`，用錯會讓每道牆的偏移都往錯的方向跑但看起來仍像個合理向量；連結樓層清單要依高程排序並標出與目前面積平面圖最接近者；高程差距大時要跳出提醒；未載入的連結不可出現在清單裡
- [ ] 區域線重新生成（依房間，JAC 04.02）— **選「目前選取的房間」時，只有選到的房間會產生區域線，其餘不動**；選「從清單複選」時房號要自然排序（A-2 在 A-10 前）且顯示各房段數；選了非本層的房間應擋下並說明；選「整層」的結果要與加這個步驟之前一致
- [ ] 清除重複區域線及面積 — **做一個「同一區域兩個面積、兩個都有編號」的情境，該組必須整組不動並列在「需人工判定」**；改成只有一個有編號時，要保留有編號的那個；兩個都空白時保留 id 較小者，且**再跑一次要顯示沒有可清除的項目**（收斂而非換一個刪）；重複區域線的結果要與「區域線重新生成」第三模式一致；刪除失敗時所有元素必須都還在
- [ ] 清除區域線及面積 — **複選同一計畫同一樓層的兩個平面圖，預覽的數量必須是去重後的（不可是兩倍）**；選「先備份」後在存檔對話框按取消，必須連刪除也一併取消；只清線時面積要完好、只清面積時線要完好；刪除失敗時所有元素必須都還在
- [ ] 面積清單 Excel — 產出的 .xlsx 要能被 Excel 正常開啟（不跳修復）；**面積欄位必須是 m² 而非 ft²**（拿一個面積跟 Revit 內容對照）；彙總分頁的小計與總計要等於各分頁列數與面積加總；面積計畫名稱含 / 或超過 31 字時分頁名要被自動修正且不重名
- [ ] 面積計算式 — 拿一個矩形子區域核對 `(H1) = 寬 x 深 = 面積`，三個數字都要與 Revit 屬性一致；**刻意做一個 L 形子區域，必須標「無法列式」而不是硬給算式**；代號序號要跨戶別連續（A1 用 H1–H3 則 A2 從 H4 起）；匯出的「列式全文」分頁要能直接貼進面積計算表
