# 樓層排序通則

## 適用範圍

所有由 Revit 匯出或更新至 Excel/CSV 的分樓層資料，若沒有使用者明確指定其他排序，皆採用本通則。

適用例：

- 空間表（房間主表）
- 面積彙總表
- 施工架、輕隔間、踢腳、內牆粉刷、天花等數量計算表
- 任何依 Room `Level`、Level 名稱或樓層欄分組的報表

## 排序順序

樓層應依建築閱讀順序排列：

1. 地下層：由深到淺，例如 `B5F → B4F → B3F → B2F → B1F`。
2. 地上層：由低到高，例如 `1F → 2F → 3F → ... → 10F → 11F`。
3. 屋突層：由低到高，例如 `R1F → R2F → RF`，其中 `RF` 排在所有 `R#F` 之後。
4. 未解析樓層：排在最後，保留原始名稱並標示需人工確認。

若 `FN` 在當次議題中明確代表需列出的基礎或筏基層，排在地下層最前方；但在室內施工架、地下室外牆防水毯分層高度等樓高型計算中，`FN` 預設不視為一般地下樓層。

## 正規化

排序前先建立樓層鍵：

- 去除空白、底線；連字號須先用來判斷棟別前綴，再從真正樓層代碼中移除。
- 去除 `樓層`、`樓` 等描述字。
- `B01F`、`B-1F`、`B1` → `B1F`。
- `01F`、`1樓`、`1F` → `1F`。
- `R01F`、`R-1F` → `R1F`。
- `RF` → `RF`。

棟別前綴必須依同一專案的 Level 命名脈絡判斷。若同批樓層出現 `B-B1F`、`B-R1F` 等可確認「B」為棟別的名稱，則同前綴名稱應先去除棟別：

- `B-B1F` → `B1F`
- `B-1F` → `1F`
- `B-R1F` → `R1F`

若沒有棟別證據，`B-1F` 才依一般地下層寫法正規化為 `B1F`。不可單看字首 `B` 就決定地下層或棟別。

不得用字串排序處理樓層，否則 `10F` 會排在 `2F` 前，地下層與屋突層也容易錯位。

## 報表寫入原則

1. 樓層名單以 Revit 目前專案或當次資料來源為準，不以 Excel 範本既有列限制專案。
2. 模板列不足時，應插列並保留格式；多餘列清空。
3. 不可把未知樓層或缺列樓層的數量靜默併入相近樓層。
4. 若數量來自明細表，彙總表應用公式引用明細小計，讓使用者看得出來源。

## 施工架套用

面積彙總表的一般室內施工架樓層列應依本規則排列，例如：

`B1F → 1F → 2F → 3F → 4F → 5F → 6F → R1F → R2F`

若專案同時有 `B5F` 到 `B1F`，則地下層區段改為：

`B5F → B4F → B3F → B2F → B1F`
