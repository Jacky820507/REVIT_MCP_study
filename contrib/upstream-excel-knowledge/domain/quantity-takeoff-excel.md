# Revit 數量計算 Excel 共通方法

## 目的

本 Domain 把多個 pyRevit 數量計算按鈕累積出的判斷整理成 RevitMCP 可重用的方法論。重點不是「把數字寫進 Excel」，而是讓每個數字都能回答三件事：來源元素是什麼、為何屬於這個房間、計算式如何形成。

## 涵蓋的數量類型

本 domain 涵蓋下列以房間或牆為基礎的數量類型。**這裡描述的是計算方法，不是 repo 內既有的功能**——
執行層由各自的流程實作，本檔不假設任何特定入口存在。

| 數量類型 | 主數量 | 核心資料來源 |
|---|---|---|
| 輕隔間 | 牆長 × 牆高 - 宿主開口 | TYPE 牆、牆高來源、Door/Window Host |
| RC 體積 | (牆長 × 牆高 - 宿主開口面積) × 厚度 - 未接合樑柱板重疊，單位 m³ | RC 牆類型關鍵字、Revit 牆面積回推毛高、`Wall.FindInserts` 開口、`AreElementsJoined` ＋實體布林交集、Grid 位置標記 |
| 踢腳 | 完成面周長 - 邊界開口寬 | Room boundary、B 代碼、門類型 |
| 內牆粉刷 | 完成面周長 × 淨高 - 邊界開口面積 | Room boundary、W 代碼、天花板／樓板底 |
| 天花 | 實體天花在房間邊界內的覆蓋面積優先；混合 C 代碼以 Room 面積扣除實體天花後反推唯一剩餘代碼；無有效實體天花時 Room 面積 | Room `天花板塗層` C 代碼、房間邊界與實體天花幾何交集、材料標記／類型名稱、天花板／樓板底高度證據 |
| 地坪 | Room 面積 × 各施工層材料；基座不自動計量 | Room `樓板塗層` F 代碼、一般模型材料版族群 |
| 門窗表 | 門窗實例數（樘） | 主模型＋選取連結模型的 Doors/Windows、Type 名稱 |
| 空間表更新 | 房號、名稱、Finish 周長、面積 | Rooms、既有 Excel 固定引用、dry-run 與備份 |
| 室內施工架 | 周長 × 高，或長 × 寬 × 高 | Rooms、用途分類、樓層排除 |
| 室外施工架 | 人工描繪外周長 × 指定高度 | Detail Lines / Filled Region |

高隔間檢核是相鄰的品質檢核流程，不是本報表引擎的通用輸出；高牆規則仍由 `tall-partition-index-workflow.md` 管理。

## 共通資料契約

RevitMCP 或 pyRevit 收集資料時，先建立可稽核的中間資料，不要直接拼 Excel 列。Room-based 記錄至少保留：

```text
RoomId, Number, Name, Level,
BoundaryLoops, BoundaryElementIds, PerimeterM, AreaM2,
FinishCodes, PhysicalCeilingAreaM2, QuantityAreaM2, QuantityAreaSource, HeightM, HeightSource,
Openings[], QuantitySource, Warnings[]
```

開口記錄至少保留 `ElementId`、Category、TypeName、HostId、WidthM、HeightM 與被扣除的 RoomId。牆記錄至少保留 `ElementId`、WallType、LengthM、HeightM、HeightSource、AreaM2 與宿主開口 IDs。

## 房間周長

1. 踢腳、內牆粉刷與空間表周長一律優先使用 `GetBoundarySegments(Finish)`。
2. 加總所有有效邊界迴圈；不得只取第一圈，也不得以 Revit `ROOM_PERIMETER` 中心線值取代完成面邊界。
3. 同時保存每個 boundary segment 的 `ElementId`，後續用來判斷門窗宿主是否真的位於該房間計算邊界。
4. `ROOM_PERIMETER` 只能在 boundary API 無資料時作明確標記的備援值，不可悄悄混用。

## 開口扣除

開口歸屬必須先證明宿主，再談房間關係。

### 輕隔間

只有 `Door/Window.Host.Id == 本次計算牆 ElementId` 才能從該牆扣除。不得用最近牆、同樓層、房間座標或 BoundingBox 接近推定。宿主不是 TYPE 牆時，即使門位在同一房間，也不得從 TYPE 牆扣除。

### 踢腳與內牆粉刷

只有 `opening.Host.Id` 存在於該房間 `BoundaryElementIds` 時才扣除。這道判斷會排除位在房間內部廁所隔牆、設備間隔牆等不構成該房間完成面邊界的門窗。

開口名稱使用 Revit 門窗品類的類型名稱，例如 `D1-90x210 cm`，不要用族名稱、實例 Mark 或自行重組名稱取代。房間關係不足、宿主缺失或尺寸缺失者列入 warnings，不自動猜測。

## 淨高證據鏈

內牆粉刷與天花高度檢核的淨高按以下順序決定，並保留 `HeightSource`：

1. 收集 `OST_Ceilings`，以房間 bbox 與天花板 bbox 的交集範圍做多點取樣；只有 `Room.IsPointInRoom` 命中的實體天花板才是候選。
2. 實體天花板優先讀 `CEILING_HEIGHTABOVELEVEL_PARAM`／`距樓層的高度偏移`：

```text
淨高 = 天花板基準樓層標高 + 天花板高度偏移 - 房間基準標高
```

3. offset 不可用時，才以天花板幾何底面或 BoundingBox bottom 作備援，來源標記為 geometry/bbox。
4. 房間沒有實體天花板時，使用：

```text
淨高 = 上層樓層標高 - 上層代表結構樓板厚度 - 房間基準標高
```

5. 所有幾何來源都失敗時，才使用明確標記的 room explicit height / Revit height fallback。

天花、Room 與樓板都必須保留完整樓層身分。多棟別專案不可先把 `A-1F`、`B-1F` 都簡化成 `1F` 再比對，否則會混用別棟的天花與樓板厚度。淨高檢核可先收集同棟別且 XY 重疊的候選，再以本房間上層樓板底為高度門檻；高於樓板底加容差者不得直接拿來決定本房間淨高，應排除並記錄在稽核表。天花數量的面積匹配要與淨高判斷分離：R-501 至 R-506 這類挑空或上方有實體天花的房間，若 `OST_Ceilings` 與房間平面範圍命中且 Room C 代碼可對應，面積仍應採實體天花面積，不可因淨高改用樓板底就退回整房 Room 面積。

計算途中保留完整精度；分組與顯示可採 0.05m 分級與小數兩位，但不得在乘法前逐步四捨五入，也不得用 `面積 / 周長` 反推一個看似精準但無法解釋的淨高。

## RC 牆體積是體積，不是面積

RC 體積計算與輕隔間共用同一張報表骨架，但有四點不同，不可互相套用：

1. **量的單位是立方公尺 m³**：`(牆長 × 牆高 - 開口面積) × 牆厚`。厚度取
   `Wall.Width`（型別厚度），缺厚度的牆不得以任何預設值補；列為缺料並回報。
2. **類型篩選是 runtime parameter**：預設關鍵字為 RC／混凝土／CONCRETE，
   執行時可由使用者改寫。英數關鍵字必須落在拉丁字詞邊界上，否則 `RC` 會誤中
   `ARCH`、`PORCH`、`SRC`，把非 RC 牆算進混凝土量。中日文關鍵字維持子字串比對。
3. **牆高取 Revit 幾何毛高**，不套用輕隔間的「樓層到上層樓板底」推算：
   `毛高 = (Revit 牆面積 + 開口面積) / 牆長`，`面積` 已反映貼附頂/底與斜板，
   所以是模型裡實際存在的高度；面積不可用時才退回不連續高度或 BoundingBox，
   並保留 `height_source`。
4. **開口來源比輕隔間廣，但證據更嚴**：RC 常被 `牆開口`、`通風格柵開口` 這類
   一般模型族群切開，只掃 Doors/Windows 會少扣；但只要是「牆上宿主族群」就扣，
   又會把不切牆的壁掛設備誤扣。判準是**同時滿足**
   `Wall.FindInserts(True, True, True, True)` 命中且 `Host.Id == 本牆`。
   非族群的開口元件（Opening/豎井）沒有寬高參數，不得用 BoundingBox 反推尺寸，
   一律列為人工確認。

5. **未接合的樑／柱／樓板重疊要扣掉**。牆直接頂到樓板或穿過樑、而兩者沒有
   Join Geometry 時，兩個元素各自回報完整體積，同一塊混凝土會被算兩次。
   判準是**先問接合狀態，再算幾何**：

   - `JoinGeometryUtils.AreElementsJoined` 為真 → **跳過，不扣**。Revit 已經決定
     誰保留共用體積：若樑贏，牆的實體（連帶 `面積` 回推的牆高）本來就已經短少；
     若牆贏，那塊混凝土本來就屬於牆。而且接合會讓兩者實體融合
     （見 `beam-penetration-algorithm.md`），此時量交集並不可靠。
   - 未接合 → 以 `BooleanOperationsUtils.ExecuteBooleanOperation(..., Intersect)`
     取實際重疊體積並扣除。候選範圍沿用 `unjoin-geometry-workflow.md` 的
     BoundingBox 外擴 1 ft ＋ `BoundingBoxIntersectsFilter`。
   - 取實體要用 `ViewDetailLevel.Fine`：Coarse 的結構構架只是一條線，沒有實體。
   - 小於 0.0005 m³（0.5 公升）視為兩個面互相接觸的數值雜訊，不計。
   - 報表要同時列出「已接合 N 對／未接合扣除 M 對」與逐項扣除明細
     （類別＋ElementId＋體積）。未接合代表模型本身有重疊實體，
     出圖前仍應回頭接合；本表只是先把重複的量扣掉，不是替代接合。
6. **異形牆不需要另一套規則**：牆高既然是 `面積 / 牆長` 的平均毛高，
   輪廓編輯過的牆（山形、斜頂、局部挖空）的總體積本來就正確，
   只是 `牆高` 欄呈現的是平均值。不要為了讓牆高看起來整齊而改用名目樓高。

### 跨房間的牆要切割分攤，不是整支歸一間

**房間歸屬一律用 `Room.GetBoundarySegments(Finish)`，不得用 BoundingBox 判斷。**
假設案例：R-102 是 L 形房間，它的 BoundingBox 完全包住 R-103，
於是每一面屬於 R-103 的牆也「碰到」R-102，最近中心點的 tie-break 把牆判給 R-102，
連帶把牆上的百葉窗也一起帶走——使用者在 R-103 那一列看不到任何開口扣除。

一支牆常同時是多個房間的邊界（外牆沿路經過三間房；內牆兩側各一間）。
處理原則是**切割分攤，不是整支歸一間，也不是每間都算一次**：

1. 每個房間對這面牆的 boundary segment 長度就是它的權重。
2. 各房間分攤長度 = `牆長 × (自身 segment 長 / 各房間 segment 長總和)`。
   分攤長度加總**恆等於牆的實際長度**，所以同一支牆只被計一次：
   - 外牆經過三間房 → 大致依實際分界切開。
   - 內牆夾在兩間房中間 → 兩間都回報整支牆長，各得一半。
3. **開口跟著自己的位置走，不跟著牆**。把開口中心投影到牆的定位線取得參數，
   落在哪個房間的 segment 區間就歸哪一間。落在所有區間之外時退回分攤比例最大的
   那間並標記——開口沒被扣會讓混凝土量灌水，不可直接丟棄。
4. 樑柱板重疊扣除量無法逐段重新量測，依各房間分攤比例帶過去。
5. 沒有任何房間邊界認領的牆進入「（未分配到房間的 RC 牆）」群組，
   不得從報表消失——體積總量必須等於所有命中牆的總和。
6. 牆面清單分頁維持**一面牆一列**（真實長度與總體積），另設欄位寫出分攤結果
   （`R-103:3.23m(33%) / R-102:2.71m(27%) / R-101:3.96m(40%)`），
   讓「分頁1 的分攤」與「分頁2 的實體」兩邊都追得回去。

切割後總量與不切割相比會有約 0.05% 的差異，來源是報表本身的兩位小數顯示，
不是演算法誤差；不得為了讓兩者完全相同而在乘法前多次四捨五入。

牆面明細分頁保留 `牆面ID`、`位置標記`（最近的兩向 Grid ＋偏移，如 `G(2.6)/15(1.5)`）、
`澆置分區`、逐開口尺寸、`合計計算式` 與 Revit 原生 `體積` 對照欄。
Grid 偏移的正負號要與 Grid 曲線的繪製方向無關，否則同一面牆會因為 Grid 反向繪製而
報到相反側。

## 輕隔間牆高是另一條規則

一般全高牆使用基準樓層到上層樓板底；斜板或局部降板可用「貼附頂/底」與幾何取樣判斷。低矮牆、襯板、腰牆或明顯未到頂牆保留自己的 Revit 牆高。詳細判斷以 `revit-partition-takeoff.md` 為準，不要把房間淨高規則直接套到所有牆。

## 材料與代碼對應

1. 踢腳讀房間 B 代碼，內牆粉刷讀 W 代碼，天花讀 Room 的 `天花板塗層` C 代碼，地坪讀 Room 的 `樓板塗層` F 代碼；以 `+` 分割多值，空白與 `-` 視為無材料。
2. 欄位只建立專案中房間實際使用的代碼；只有類型定義但沒有實體數量時不列空欄。
3. 材料名稱可由使用者選擇的一般模型材料版族群類型對應。去掉 `B1=`、`W1=`、`C1=`、`F1=` 等前綴，只保留材料名稱。
4. 房間沒有踢腳、牆面或天花代碼仍須列出房間明細，數量欄保持空白或 0；完整房間清單與材料數量是兩個不同需求。

### 天花代碼的主從關係

天花數量的材料欄以 Room `天花板塗層` 為主資料來源，不需要再依賴某張粉刷明細表決定房間集合。實體 `OST_Ceilings` 的 C 代碼證據是 QA 對照來源，不可反向覆蓋 Room 代碼：

1. Room C 代碼決定 Excel 填入哪個材料欄；目前天花範本為 A 編號、B 空間名稱、C 面積，材料欄自 D 欄起，數量公式直接引用 `面積欄`。
2. 面積欄優先使用房間上方命中的 `OST_Ceilings` 與 Room `GetBoundarySegments(Finish)` 垂直裁切體之幾何交集面積；不得在配對成功後直接套用整個 Ceiling 元件的 `HOST_AREA_COMPUTED`。同一片天花跨越多個房間時，每間房只取得自身邊界內的覆蓋面積。候選天花若同時出現在不同樓層，先保留與 Room 同基準樓層的天花；同層沒有實體天花時，才取最近上方候選所在樓層，避免把 B-1F、B-2F、B-3F 的垂直重疊天花全部相加。幾何裁切失敗時才使用明確標記的水平覆蓋估算，而且估算值不得超過 Room 面積；完全沒有有效實體天花時才回退 Room 面積。
3. 命中實體天花時，彙整房間平面範圍內所有實體天花的 C 代碼，再與 Room C 代碼集合比較。
4. 兩者不一致時，材料欄仍依 Room 參數填入，但必須標示「需更改實體天花」，列出房號、Room C 代碼與實體天花 C 證據。
5. 實體天花的 C 代碼可來自天花類型 Type Mark、天花材料層的材料標記或類型名稱；不要只因 Type Mark 空白就在主表備註提醒。只有實體證據完全無法辨識 C 代碼，或與 Room `天花板塗層` 不一致時，才列為需處理事項。
6. Room `天花板塗層` 空白但命中有效實體天花時，不可用實體 Type Mark 代填材料欄；主表材料數量保持空白，並提示回填 Room 參數後重新匯出。

### 混合天花與填滿範圍

填滿範圍是視圖專屬 2D 元素，不是 `OST_Ceilings` 模型元素，也常為跨房間一次繪製的表現法。天花 Excel 預設不掃描 FilledRegion 幾何面積，避免執行過慢與把圖面表現誤判為數量邊界。

1. Room 有 `C4+C9` 等混合代碼時，先建立實體天花 `code -> area`。
2. 若實體天花已命中其中一部分代碼，且 Room 只剩唯一一個 C 代碼沒有實體面積，直接採 `剩餘代碼面積 = Room 面積 - 已知實體天花面積`。
3. 例如 R-140：Room `天花板塗層=C4+C9`、Room 面積 150.00 m²、C4 實體天花面積 130.00 m²，則 C9 = 150.00 - 130.00。
4. 若剩餘代碼不只一個，或實體代碼無法對上 Room 代碼，主表備註只提醒「缺少可分區面積證據」或「需更改實體天花」。
5. 主表備註只放重點異常，例如 Room C 代碼與實體證據不一致、無法分攤、缺 Room 參數。正常反推、垂直排除與概算容許差異留在稽核資料，不塞入主表備註。

### 地坪多施工層與基座

地坪的多個 F 代碼與混合天花意義不同。打底面、完成面、防水層等可能都以同一個 Room 面積計量，因此 Room `樓板塗層` 同時包含多個一般地坪 F 代碼時，每個非基座材料欄都可以引用同列 Room 面積，不應因數值重複就判定錯誤。

1. 使用者先從 UI 選擇一般模型品類的材料版族群，程式從其類型名稱、Type Mark 或文字參數辨識 `F#=材料名稱`。
2. Room `樓板塗層` 是材料欄權威來源；所有有效房間都列入明細，欄位只建立 Room 實際使用的 F 代碼。
3. 每個非基座 F 代碼以 `=C列` 引用 Room 面積，保留打底面與完成面各自計量的可稽核公式。
4. 若對應材料名稱含「基座」，保留該 F 欄與材料名稱，但不得自動填入整間 Room 面積；備註固定寫「此房間有基座需自行手動計算填入數值」。
5. 材料版找不到 Room F 代碼名稱時，仍保留代碼欄並在備註與稽核分頁提示，不得用其他相近代碼猜測。
6. 房間明細依 `floor-level-ordering.md` 排序；多棟別 Level 先保留完整名稱，只有同專案命名脈絡能證明棟別前綴時才移除前綴建立排序鍵。

## Excel 報表契約

- 標題與預設檔名取目前 Revit `doc.PathName` 的檔名；只有未儲存文件才 fallback 到 `doc.Title`。
- 明細保留公式，例如 `周長 - SUM(開口)`、`周長 × 淨高 - SUM(開口面積)`，不要只輸出硬編結果。
- 單一天花材料且數量等於 C 欄時，材料儲存格保留 `=C列` 公式；混合天花依實體天花與 Room 剩餘面積反推寫入各 C 材料欄，不得各自引用整間面積。主表右側保留精簡備註，稽核分頁保留完整高度、面積來源與代碼證據。
- 地坪依 `粉刷明細表比對(地坪).csv` 的結構建立 A 編號、B 空間名稱、C 面積、D 起 F 材料欄，材料名稱列後留一空白列，右側保留「對應圖說」與「備註」。多個非基座施工層可各自引用 `=C列`；基座欄保持空白。
- 表尾加入對應的「數量總計」，左側固定欄跨欄置中，各材料／牆型欄使用 `SUM`。
- 新建 `.xlsx` 可使用 OpenXML，避免依賴 Excel COM；更新既有 `.xls/.xlsx` 且需保護跨分頁公式時，可用 Excel COM，但必須 dry-run、備份、再寫入。
- 更新既有空間表時以 Revit ElementId 為優先身份、房號為人可讀鍵；不得任意重排固定引用列。

## RevitMCP 實作邊界

若把 pyRevit 邏輯轉成 MCP command，分成三層：

1. C# / Revit API：收集元素、房間 boundary、宿主、尺寸與高度來源，回傳結構化 JSON。
2. MCP Server schema：暴露範圍、代碼欄、排除條件、dry-run 與輸出選項，不寫死專案名稱或材料族名稱。
3. Skill / 報表層：選擇算量類型、套用公式、建立 Excel、顯示 warnings 與驗證摘要。

同一個工具回傳中應包含來源統計，例如 `boundary/fallback`、`actual-ceiling-offset/slab-bottom`、`deducted/skipped openings`。沒有本 turn 的 Revit 回讀資料時，不得宣稱已計算目前專案。

## 交付驗證

- 抽查一間有內部廁所隔牆門的房間，確認該門不從房間完成面邊界數量扣除。
- 抽查一間有實體天花板的房間，確認淨高等於天花板 offset 邏輯且 `HeightSource` 正確。
- 抽查一間無天花板房間，確認使用上層樓板底且樓板厚度來源可追溯。
- 抽查 Room C 代碼與實體天花 C 證據不一致的房間，確認數量仍落在 Room C 欄，並提示實體天花需更改。
- 抽查 R-501 至 R-506 這類上方有實體天花的挑空房間，確認面積採實體天花面積；同時確認淨高檢核不會把上層天花誤作本房間樓板底。
- 抽查 R-131 這類單一實體天花跨越多房間、且上方各樓層又有重疊天花的案例，確認數量面積只採同層天花與該房間邊界的幾何交集，不是整片 Ceiling 元件面積，也不是各樓層天花總和；稽核表須列出面積來源與排除訊息。
- 抽查 R-140 這類 `C4+C9` 混合天花案例：C4 來自實體天花，C9 應以 `Room 面積 - C4 實體面積` 反推，材料總和等於 Room 面積。主表備註只保留真正需要修正的問題。
- 抽查一間同時有打底面與完成面 F 代碼的房間，確認兩個非基座材料欄都引用同一列 Room 面積。
- 抽查一間 `樓板塗層` 命中材料名稱含「基座」的房間，確認基座欄空白且備註為「此房間有基座需自行手動計算填入數值」。
- 抽查材料版找不到名稱的 F 代碼，確認該欄不自動填值，避免未知材料其實是基座。
- 依 `floor-level-ordering.md` 抽查 `B-1F`、`B-B1F`、`B-R1F` 等樓層命名；棟別證據不足時不得過早移除前綴。
- 確認所有有效 Rooms 都列出，包括無 B/W 代碼與零數量房間。
- RC 體積：抽查一面有門窗的 RC 牆，確認 `(長×高-開口)×厚` 與該牆 Revit 原生 `體積`
  接近；差異明顯時先查開口是否漏扣、牆是否被接合切掉，不得回頭調牆高。
- RC 體積：確認類型欄沒有 SRC／ARCH 這類非 RC 牆，且 `nearest` 歸屬與
  「未分配到房間」的牆數與總量都有回報。
- RC 體積：抽查一面「牆穿過樑但沒有接合」的牆，確認扣除明細列出該樑的 ElementId
  與體積；再抽查一面已接合的牆，確認它**沒有**被重複扣除。
- RC 體積：抽查一間被 L 形房間的 BoundingBox 包住的房間（前述假設案例的 R-103），
  確認它牆上的開口記在自己這一列，而不是被 L 形的那間拿走；
  再確認被切割的那支牆，各房間分攤長度加總等於牆的實際長度。
- 掃描 `#REF!`、`#VALUE!`、`#NAME?`、`#DIV/0!`，並比對明細 SUM 與材料／牆型總計。
- 回報 skipped openings、missing sizes、missing hosts、missing heights 與 fallback 數量，不能只說「匯出成功」。

## 實作可達性

本 domain 的規則來自多個已實跑的數量計算流程，但**這些流程的執行層不在本 repo 內**
（原始實作是外部 pyRevit extension 的按鈕）。本文件因此只保留可重用的判斷規則，
不引用任何外部檔名、函式或按鈕路徑——避免讀者或維護者把「文件提到的東西」
誤認為「repo 內可直接呼叫的東西」。

各段規則在本 repo 的可達性：

| 規則段落 | 取數所需能力 | 本 repo 是否提供 |
|---|---|---|
| 房間周長／面積、完成面邊界 | `calculate_room_scaffold_perimeters`（`includeRoomDetails: true`） | ✅ |
| 房間清單與樓層分組 | `get_rooms_by_level`、`get_room_info` | ✅ |
| 房間飾面代碼（B/W/C/F） | `get_room_surface_areas`、`get_field_values` | ✅ |
| 明細表數量來源 | `query_schedule_data` | ✅ |
| 開口／門窗宿主與尺寸 | `query_elements_with_filter`、`get_element_info` | ✅ |
| 淨高推導所需天花／樓板幾何 | `get_element_geometry` | ✅ |
| **Excel 產出與既有活頁簿更新** | — | ❌ 無對應 MCP 工具，見 `revit-excel-workbook-update.md` |

換言之：**取數這一半在本 repo 走得通，寫 Excel 那一半需要外部腳本**。
規劃工作流程時請明確區分這兩段，不要假設有一個「一鍵出 Excel」的工具存在。

## 門窗數量回填 小計 金屬門窗工程

門窗表與前述數量類型不同：它不建立新報表，而是就地更新既有預算表的數量欄。

1. **型號比對鍵**取 `<編號>-<寬>x<高>cm`，即字串到第一個 `cm` 為止，
   兩邊都做 NFKC 正規化並移除空白。Revit `D2-160x210 cm` 與
   Excel `D2-160x210cm(WxH)雙開鋼板防火門` 因此對得上；
   `W3-R=90cm固定圓形窗` 沒有 `(WxH)` 也仍解析得出。
2. **不可用 TypeMark 當識別**。假設案例中 `SD1-1000x250 cm` 的 TypeMark 是 `88`、
   開口族群是 `77`，而 Type 名稱才保有預算表的型號格式。
3. **區塊邊界**：工項列從「金屬門窗工程」標題下一列起，到下一個「…工程」標題前一列止。
   判定標題要先剝掉括號後綴再看是否以 `工程` 結尾，並要求該列**沒有單位**——
   `複層式金屬鋼浪板工程(以面積計算)` 用單純 `endswith` 會漏判，
   會讓區塊從約 34 列暴增到 55 列，把鋼浪板與鋁包板的項目一起算進來。
4. **兩個方向的落差都要回報**：Excel 有工項但 Revit 沒有該型號時，
   **不得歸零**（可能是連結模型沒勾、或該型號在別的分區），只列出待確認；
   Revit 有但 Excel 沒有對應列時，列出型號與數量提示人工新增工項列。
5. **只寫純數字的數量儲存格**。該欄若已是公式代表被接到別的分頁，一律列為 blocker。
   同一型號鍵對應到多列時同樣阻擋，不猜要寫哪一列。
6. **樓層篩選以 `(來源模型, LevelId)` 複合鍵識別**，不可只用樓層名稱：
   假設主模型有 `A-1F`、連結模型有 `B-1F`，名稱平行且 ElementId 會跨文件重複。
   未勾選任何樓層＝不篩選、全部抓；若勾選的樓層全部屬於別的模型，
   該來源要明確回報「未選取樓層，略過」，而不是靜默貢獻 0。
   取消勾選某連結模型時，必須同步剪掉屬於它的樓層勾選，否則會留下永遠比不中的 stale key。
   門窗的樓層解析需要 fallback 鏈：`LevelId` →
   `FAMILY_LEVEL_PARAM` / `INSTANCE_REFERENCE_LEVEL_PARAM` / `SCHEDULE_LEVEL_PARAM` →
   宿主牆的 `LevelId`；門開在牆上時 `LevelId` 常是無效值。
7. **小計的數量是全案總量，不可被單一來源取代**。只勾部分連結模型或部分樓層時，
   若直接把該子集的數量寫進 F 欄，其他棟別的門窗就被洗掉（假設：全案 22 樘的 D2
   會被單一連結單層的 6 樘覆蓋）。
   作法是新增「門窗表稽核」分頁當帳本，每列記
   `來源模型｜樓層｜型號鍵｜型號名稱｜數量｜更新時間`，小計 F 欄寫各來源加總後的**純數字**。
   - 重跑同一個 `(模型, 樓層)` 只取代它自己那幾列，具冪等性，不會重複累加。
   - 未套用樓層篩選的整模型執行，範圍記為 `（全部樓層）`，
     且必須清掉該模型所有既有的分層列，否則舊的分層數會疊在整模型數之上。
   - F 欄刻意不寫 `SUMIF` 跨表公式：本工作流的安全規則是「只覆寫純數字」，
     寫成公式會讓下一次執行判定為受保護而自我阻擋。
8. 寫入契約與其他更新既有 Excel 的按鈕一致：單一 Excel session、
   先備份、寫入後回讀驗證、失敗自動還原。
