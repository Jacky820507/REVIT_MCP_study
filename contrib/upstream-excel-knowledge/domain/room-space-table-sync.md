# 房間空間表同步（Revit → 預算 Excel）

## 適用情境

預算計算 Excel 以「空間表」分頁為房間主表（樓層／房間編號／房間名稱／周長／面積），
下游數量分頁（踢腳、內牆、地坪、天花…）用 `='空間表'!B3` 這類**固定儲存格引用**
逐列取值再乘係數（如 內牆面積 = 周長 × 天花高）。當 Revit 模型的房間有修改，
需把最新的房間資訊回寫空間表，讓整本預算連動更新。

## 核心原則（違反會弄壞整本 Excel）

1. **以 RevitId 為身份主鍵、就地改值**（v3）：房間編號會重編、名稱會改，
   都不是穩定身份——穩定身份是 Revit ElementId。空間表設一欄 `RevitId`
   （工具自動建立與維護，通常在 F 欄），四階段匹配：
   ① Id（重編號免疫）→ ② 編號＋名稱（首次 bootstrap 或刪除重建）→
   ③ 名稱＋數值（容差先嚴 0.005 後寬 0.05，分得開兩間同名僅差 0.01 的房間）→
   ④ 名稱唯一（雙邊都只剩一筆同名，容許重編號＋幾何同時改變）。
   匹配後只改該列的編號／名稱／周長／面積儲存格並回填 Id。
   **重編號＝就地改編號欄、列位不動**→下游手填資料（開口明細、天花高、
   材料欄）跟著房間本體走，不會錯位。四階段都對不上但數值吻合的
   （疑似改名＋重編同時發生）標 `unresolved` 不寫入，列入驗證表待人工裁決。
2. **插入安全、刪除禁止**：在空間表「插入」列時，Excel 會自動位移修正
   所有分頁的 `='空間表'!B50` 型引用（→`B51`），零錯位；
   「刪除」列則讓引用變 `#REF!`——所以新增房間用插列、移除房間絕不刪列。
3. **新房間＝雙邊插列**：空間表依編號序插入正確位置
   （同前綴找「小於它的最大編號」為前導，插其後；無前導插後繼之前；
   都沒有→附加表尾並標示人工處理）。空間表插完後，掃描所有引用分頁，
   在前導房區塊尾（跳過其開口明細列）插入對應列：複製前導主列
   （帶格式與列內相對公式）→ 逐格重設引用指向新列 → 依分頁規則清空手填欄
   （踢腳清 E~I 開口；內牆保留 H 天花高沿用前導值、清 K~N；
   地坪/天花清 D 面積修正與材料欄；未知分頁保留複製值並提醒抽查）。
   插入點鄰分節邊界時，該節小計 SUM 範圍需人工抽查。
4. **Excel 有、Revit 沒有的房間＝整列刪除＋下游連動刪（v3.1）**：
   墓碑列保留舊編號會造成編號重複（例：已拆除的 R-102 與遞補的 R-102 並存），
   故改為刪除。安全程序：
   ① 全簿掃描該空間表列的所有引用（含嵌在運算式中的）；
   ② 引用全部落在各分頁「該房間的主列＋開口明細列」區塊內 → 依序刪
   下游區塊、再刪空間表列（Excel 自動位移修正其餘引用，編號完全讓位）；
   ③ 刪列後緊接列若出現**裸 `#REF!`**（遞增序號類公式 `=A22+1` 斷鏈）
   → 自動重指向上一列同欄修復；帶分頁前綴的舊傷（`='空間表'!#REF!`）不碰；
   ④ 偵測到區塊外的殘留引用 → 該列**不刪**，退回墓碑保留
   （編號加註 `(拆)`＋名稱加註`【已拆除】`＋歸零）並回報殘留位置，防 `#REF!`。
   依此程序執行後全簿 `#REF!` 數量與基準完全相同（零新增破壞）。
5. **樓層欄不改寫**：Revit 樓層名（如 `B-B1F`）與 Excel 慣用名（如 `B1F`）
   命名不同，不強行同步；插入的新列以 Revit 樓層名原樣寫入並標示待人工核對。
6. **寫入前必先備份**（同資料夾 `_backup_YYYYMMDD-HHMM` 副本），
   並先 dry-run 預覽差異、使用者確認後才寫入。
7. **檔案路徑與分頁由使用者於執行時指定**，不寫死
   （見 `user-specified-runtime-parameters.md`）。

## 資料來源（Revit 端）

用既有命令 `calculate_room_scaffold_perimeters`，參數
`{excludeLevels: [], excludeKeywords: [], includeRoomDetails: true}`
（排除條件歸零＝回傳全部已放置房間）。每房取
`Number / Name / Level / PerimeterM / AreaM2`；
周長 = `GetBoundarySegments` @Finish（飾面線），與空間表周長語意一致。
面積、周長寫入值四捨五入至小數 2 位，差異門檻 0.005。

## Excel 端（COM）

- 用 Excel COM 就地編輯（.xls/.xlsx 皆可、公式與格式保真度最高；
  ClosedXML 不支援 .xls，不適用）。
- 表頭偵測：於前 5 列尋找「房間編號／房間名稱／周長／面積」字樣定位欄，
  找不到才 fallback（表頭第 2 列、B/C/D/E 欄）。
- 最後資料列以編號欄 `End(xlUp)` 偵測；編號重複列跳過並列入報告。
- 附加列的周長/面積 NumberFormat（`0.00"m"` / `0.00"㎡"`）比照上一列複製。
- 目標檔開啟中（唯讀鎖定）→ 中止並提示關閉，不得寫入。

## 下游分頁結構（典型樣式，實際以專案為準）

- **地坪/天花**：每房 1 列（A 編號 B 名稱 C 面積引用＋D 面積修正、E~N 材料欄手填），
  中段可穿插他棟空間表（`其他棟別空間表`）的區塊。
- **踢腳/內牆**：每房「主列（引用）＋0~N 列手填開口明細列」變動長度區塊；
  主列含列內相對公式（踢腳 `H=F*G`、`I=SUM(開口)`、`J=C-I`；內牆 `I=E×H天花高`）。
- 開口明細列特徵：A~C 欄空、D~N 欄有內容——插列演算法以此判定前導房區塊尾。

## 逐筆狀態（dry-run 驗證表）

每筆顯示匹配依據（Id／編號+名稱／名稱+數值／名稱唯一）與編號變更（舊→新）：
`ok` 一致／`idfill|idfilled` 一致僅回填 Id／
`update|updated` 需更新、已更新（逐欄記 舊→新，含重編號）／
`insert|inserted` 新房間雙邊插列／`manual_append|appended` 附加表尾（需人工補下游）／
`delete_row|deleted_row` 已拆除整列刪除（含下游連動刪＋序號修復）／
`mark_zero|marked_zero` 已拆除但有殘留引用，退回墓碑保留（`(拆)`編號＋歸零）／
`unresolved` 疑似改名＋重編（不寫入，待人工）／`dup_rid` RevitId 重複（跳過）。

## 教訓（假設案例）

以「編號」當身份鍵時，使用者刪除消防機房並將 31 間房整批重編號，
工具把每列改寫成「新編號的佔用者」——空間表看似正確，但下游分頁的
手填資料全部錯位一格。修復：還原備份、改用 RevitId 身份鍵重同步。
改用 Id 主鍵後，同批資料重驗：重編號全數識別、真新增與真拆除各自正確分類、
0 筆誤判。**任何以使用者可改欄位當主鍵的同步設計都有此風險。**

## 執行順序

不論由哪一種前端驅動，順序都相同：

選檔 → 選分頁 → dry-run 逐筆差異表 → 使用者確認 → 備份 → 寫入 → 完成報告。

## 實作可達性

| 步驟 | 所需能力 | 本 repo 是否提供 |
|---|---|---|
| 取房間編號／名稱／樓層／周長／面積 | `calculate_room_scaffold_perimeters`，參數 `{excludeLevels: [], excludeKeywords: [], includeRoomDetails: true}` | ✅ |
| 空間表就地改值（COM、保護公式與跨頁引用） | — | ❌ 無對應 MCP 工具 |

取數這一段可直接用既有 MCP 工具完成；Excel 就地更新那一段目前**沒有** Revit 端命令，
需由外部腳本（例如 PowerShell 驅動 Excel COM）依本檔原則執行。寫入契約與備份、
dry-run、寫入後驗證規則見 `revit-excel-workbook-update.md`。

本檔描述方法，不綁定任何特定按鈕或腳本檔名。
